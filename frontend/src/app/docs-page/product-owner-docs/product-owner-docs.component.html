Product Backlog Inicial

El Product Backlog representa el conjunto de funcionalidades y requisitos funcionales identificados para el proyecto FreeCAD. Estas especificaciones fueron definidas mediante historias de usuario bajo el marco de la metodología Scrum, permitiendo organizar, priorizar y abordar de forma iterativa las características del sistema.

Prioridad Alta (Capabilities Avanzadas)

Ensamblajes, simulación FEM, impresión 3D, automatización por Python y gestión de complementos. Extienden el modelado y análisis.

Prioridad Media (Intercambio y Documentación)

Importación/exportación de archivos CAD y generación de planos técnicos. Complementan el flujo de información externa.

Prioridad Baja (Capa Fundamental)

Sketcher, modelado 3D y control paramétrico. Corresponden a los cimientos esenciales sobre los cuales se construye todo el sistema.

Descripción Detallada del Backlog

A continuación se desglosan las características técnicas, operativas e historias de usuario asignadas a cada componente del Product Backlog.

B-01

Crear bocetos 2D mediante Sketcher

Permite el trazado de geometría bidimensional (líneas, arcos, curvas) como base analítica para el diseño 3D. Incorpora un solucionador de restricciones geométricas y dimensionales.

User Story: Como diseñador, quiero crear bocetos 2D restrictivos para estructurar bases sólidas de modelos tridimensionales.
Prioridad: Baja (Core fundamental)
B-02

Implementar modelado paramétrico 3D

Transforma los perfiles 2D del Sketcher en sólidos tridimensionales mediante operaciones constructivas como extrusión, revolución, vaciado y redondeos.

User Story: Como diseñador mecánico, quiero generar sólidos 3D paramétricos para editar características sin reconstruir la pieza.
Prioridad: Baja (Core fundamental)
B-03

Sistema de modificación mediante parámetros

Abstrae las cotas y variables del diseño permitiendo gobernarlas mediante valores globales interconectados. El cambio de una sola variable propaga la actualización por todo el modelo.

User Story: Como usuario, quiero controlar las dimensiones mediante variables globales para acelerar cambios complejos de ingeniería.
Prioridad: Baja (Core fundamental)
B-04

Importación y exportación de archivos CAD

Garantiza la interoperabilidad del sistema mediante la lectura y escritura de formatos universales de la industria como STEP, IGES y STL.

User Story: Como ingeniero, quiero intercambiar archivos en formatos estándar (STEP, STL) para colaborar con software de terceros.
Prioridad: Media (Interoperabilidad)
B-05

Generación de planos técnicos

Traduce la geometría tridimensional en documentación normalizada 2D con proyecciones automáticas, cotas y anotaciones vinculadas al modelo.

User Story: Como dibujante, quiero proyectar planos 2D normalizados con cotas para documentar rigurosamente la fabricación.
Prioridad: Media (Documentación)
B-06

Implementar sistema de ensamblajes

Permite agrupar piezas independientes con restricciones espaciales (coincidencia de caras, concentricidad, distancias fijas) para validar tolerancias y simular cinemática.

User Story: Como diseñador mecánico, quiero articular múltiples piezas bajo restricciones de posición para validar su acoplamiento.
Prioridad: Alta (Análisis avanzado)
B-07

Simulación mediante elementos finitos (FEM)

Integra capacidades analíticas avanzadas para predecir comportamiento físico: fuerzas, restricciones y flujos térmicos sobre la geometría con mallas numéricas.

User Story: Como analista estructural, quiero someter el modelo a cargas físicas virtuales para asegurar su integridad operativa.
Prioridad: Alta (Análisis avanzado)
B-08

Herramientas para impresión 3D

Prepara y valida el sólido geométrico para manufactura aditiva. Analiza estanqueidad de mallas y optimiza la conversión a formatos STL de alta fidelidad.

User Story: Como operador, quiero verificar y exportar mallas estancas óptimas para agilizar la manufactura de prototipos físicos.
Prioridad: Alta (Producción)
B-09

Automatización mediante Python

Expone la API interna de C++ a un intérprete Python integrado. Facilita macros, generación paramétrica de componentes y comandos personalizados.

User Story: Como desarrollador, quiero interactuar con la API mediante Python para automatizar rutinas de modelado monótonas.
Prioridad: Alta (Extensibilidad)
B-10

Gestión de complementos y módulos adicionales

Administra la arquitectura modular extensible con interfaz para descubrir, instalar y actualizar workbenches y macros de la comunidad.

User Story: Como usuario avanzado, quiero un gestor integrado para inyectar entornos especializados a mi espacio CAD dinámicamente.
Prioridad: Alta (Extensibilidad)

Distribución del Backlog por Sprints

En la metodología Scrum el Product Backlog se distribuye a lo largo de los sprints según la prioridad, dependencias técnicas y capacidad del equipo. A continuación se muestra cómo los requisitos identificados fueron asignados a cada hito del proyecto.

Sprint 0

Fundación y Core del Modelado

Semana 1-2 · 15 días
8 SP

Establecer la base paramétrica del producto. Sin el Sketcher ni el modelado 3D ningún otro componente puede funcionar, por lo que estas capacidades se abordan primero a pesar de tener prioridad "baja" en el backlog inicial.

B-01 Crear bocetos 2D mediante Sketcher
B-02 Implementar modelado paramétrico 3D
B-03 Sistema de modificación mediante parámetros
Sprint 1

Interoperabilidad y Documentación

Semana 3-4 · 15 días
5 SP

Una vez que el modelo paramétrico está operativo, se necesita poder importar/exportar archivos con otros programas CAD y generar planos técnicos a partir de la geometría 3D.

B-04 Importación y exportación de archivos CAD
B-05 Generación de planos técnicos
Sprint 2

Análisis y Manufactura Avanzada

Semana 5-6 · 15 días
10 SP

Con el núcleo de modelado e interoperabilidad estable, se incorporan capacidades analíticas de alto valor: ensamblajes complejos, simulación por elementos finitos y preparación para manufactura aditiva (impresión 3D).

B-06 Implementar sistema de ensamblajes
B-07 Simulación mediante elementos finitos (FEM)
B-08 Herramientas para impresión 3D

8 SP

B-10 Gestión de complementos y módulos adicionales

Evolución de Requerimientos entre Sprints

Una de las fortalezas de Scrum es la capacidad de adaptar los requerimientos según el feedback recibido en cada Sprint Review. A continuación se muestra cómo evolucionaron los requisitos del proyecto a lo largo de los sprints.

B-06: Ensamblajes refinado

Originalmente definido como "sistema de ensamblajes simple". Durante el Sprint 1 Review, el equipo identificó la necesidad de restricciones espaciales avanzadas (concentricidad, distancia fija), lo que amplió el alcance. Se refinó en Sprint 2.

Sprint 1 → Sprint 2 +3 SP

B-08: Impresión 3D agregado

No estaba contemplado en el backlog inicial. Se agregó durante Sprint 2 Planning por solicitud del stakeholder académico, que necesitaba validar prototipos físicos para la materia de Manufactura.

Agregado en Sprint 2 Nuevo

B-09 y B-10: Repriorizados a Alta

Originalmente prioridad media, se repriorizaron a alta durante Sprint 2 Retrospective porque el equipo reconoció que la automatización Python era crítica para las pruebas y la gestión de complementos para la demostración final.

Repriorizado en Sprint 2 Media → Alta

B-11 (planeado): Renderizado fotorealista

Se había planificado un módulo de renderizado, pero se eliminó en Sprint 2 Planning por restricciones de tiempo. El equipo acordó documentarlo como deuda técnica para futuras iteraciones del proyecto.

Eliminado en Sprint 2 Postergado

Lección de Scrum aplicada

Esta evolución demuestra cómo Scrum permite adaptar el producto al contexto real del proyecto. Los requerimientos no son estáticos: cambian por feedback de stakeholders, descubrimientos técnicos del equipo y restricciones de tiempo. El Product Owner gestiona estos cambios priorizando continuamente el valor entregado en cada sprint.
